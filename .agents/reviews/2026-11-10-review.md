## Headline

**Vibe's headline ("no crash-class, wrong-result-class or memory-safety bug reachable
through the exported API") is wrong.** Codex's B1 is a memory-safety bug that the exported
functions reach, and it was reproduced again for this file with the installed package:

```r
library(zucrypt)
length.review_raw <- function(x) 1L
crypt_equal(structure(raw(0), class = "review_raw"), as.raw(1))
#> TRUE                                   # wrong result

length.iv16 <- function(x) 16L
crypt_aes_cbc_encrypt_nopad(raw(16), as.raw(1:16), structure(raw(1), class = "iv16"))
#> returns 16 bytes                       # 15-byte over-read of the IV

crypt_equal(structure(raw(2^28), class = "review_raw"), as.raw(1))
#> *** caught bus error ***  R aborts     # crash
```

Vibe's type-confusion probe tested unclassed integers only. Those are caught by the
checked accessors, so it missed this case: a classed *raw* vector passes `is.raw()` but
reports any `length()` its method returns.

## Findings

### B1 — R-side length checks are the only guard on native buffer access

- **Severity:** memory safety. The exported functions reach it.
- **Location:** `src/zucrypt_crypt.c` — `zucrypt_equal()` (~l.411) uses `XLENGTH(x)` for
  both buffers and never reads `XLENGTH(y)`; `zucrypt_aes_cbc()` (~l.373) passes `RAW(iv)`
  to `zuc_aes_cbc_set_state()` without a length, so 16 bytes are read unconditionally;
  `zucrypt_hex()` sizes `R_alloc(2 * n + 1)` and `Rf_mkCharLenCE(..., (int)(2 * n))` with
  only the R-side `length(x) > 1073741823` guard (`R/hex.R:33`) in front of it.
- **Why:** `length()` is an internal generic. A classed raw vector passes `is.raw()`, so
  `check_raw()`, `check_aes_iv()`, `check_block_multiple()` and the `crypt_equal()`
  `length(x) != length(y)` shortcut all read the S3 method's answer, while C reads the
  true `XLENGTH`. Key length and data-block multiple are re-checked in the adapter
  (`ZUC_ERR_BAD_LENGTH`), so those paths are safe. The IV and the equal-length assumption
  are not re-checked anywhere.
- **Trigger:** see the headline. `crypt_hex()` should also be probed with a classed
  vector over 2^30 bytes that reports length 1: the `int` cast of `2 * n` then overflows.
- **Fix:** enforce every precondition that governs memory access in C, with `TYPEOF()`
  and `XLENGTH()`, before touching a buffer: in `zucrypt_equal`, return `FALSE` when
  `XLENGTH(x) != XLENGTH(y)`; in `zucrypt_aes_cbc`, require `XLENGTH(iv) == 16`; in
  `zucrypt_hex`, require `n <= 1073741823`. Keep the R checks for their messages.
  Alternatively, or as well, compute lengths in R with `length(unclass(x))`. Audit every
  `.Call` on `main` that takes a buffer without its length, including the Stage 13–16
  entry points.
- **Test:** regression tests with classed raw vectors whose `length()` method lies, for
  each entry point: `crypt_equal` in both argument orders, the CBC IV, `crypt_hex`, plus
  the new GCM, PBKDF2, RSA and EC inputs. Each must either error or give the answer for
  the true bytes.

### B2 — Context state is inconsistent after a backend update failure

- **Severity:** correctness, medium. Reached through the archive and table handle APIs;
  the R streaming path surfaces the error and drops the handle.
- **Location:** `src/zuc_hash.c` `zuc_hash_update()` (~l.123–137) and the HMAC equivalent
  (~l.340). They return the PSA status but leave `->active` set. A failed
  `psa_hash_update`/`psa_mac_update` aborts the backend operation.
- **Evidence (codex, standalone C probe with a `calloc` override failing the next
  allocation):**
  ```text
  failed update:     ZUC_ERR_MEMORY
  next empty update: ZUC_OK            <- reports success on a dead operation
  next byte update:  ZUC_ERR_INTERNAL
  reset:             ZUC_OK
  ```
  The probe source is in `review-codex.md` (`update-failure.c`, linked against
  `libzucrypt.a`, built with `-fno-builtin-calloc`).
- **Fix:** define the error-state contract. Recommended: any backend failure in
  update/finish marks the handle inactive, so later updates return
  `ZUC_ERR_INVALID_ARGUMENT` until `reset`. Apply the same rule to hash and HMAC, and
  document it in `zucrypt.h`. This is an ABI-1 clarification, not a layout change.
- **Test:** turn the probe into a `zucrypt_test_*` harness entry with an injected failure
  point, then assert the update → update(0) → update(1) → reset → update → finish
  sequence ends in the known digest.

### B3 — Header changes do not rebuild native objects

- **Severity:** build correctness, medium.
- **Location:** `src/Makevars` has no `.o: .h` rules. Objects depend only on their `.c`
  files.
- **Evidence (codex):** after `zuc_crypto_config.h` was edited to force software AES, a
  plain `R CMD INSTALL` reused the old objects and `crypt_info()` still reported `aesce`;
  `--preclean` gave `software`. A partial rebuild across a config change can also mix
  objects compiled against different backend struct layouts.
- **Fix:** add conservative, portable-make dependencies. Every object depends on
  `Makevars` and `zucrypt.h`. Adapter and vendor objects depend on
  `zuc_crypto_config.h` and the vendored headers; one generated, committed header list
  (written by `tools/vendor/record`) is enough. Each glue file depends on the headers it
  includes, and `libzucrypt.a` depends on its objects. Document that flag changes made
  through the environment still need `--preclean`.
- **Test:** in a scratch checkout, install, set `ZUC_AES_SOFTWARE_ONLY`, then reinstall
  *without* `--preclean`. `crypt_info()$build_flags$aes_implementation` must read
  `software`. Revert, reinstall, and the hardware path must come back. Repeat the check
  through `zucryptlink`.

### B4 — Consumer `configure` mangles valid library paths

- **Severity:** integration, medium. It affects the fixture and the recipe published in
  `vignettes/articles/c-api.Rmd` (~l.72), so it reaches every downstream that copies it,
  including zuxlsx.
- **Location:** `tools/zucryptlink/configure:38`:
  `sed -e "s|@ZUCRYPT_LIB@|${ZUCRYPT_LIB}|g"`, which inserts the path unescaped into a
  `sed` replacement whose result is single-quoted in `PKG_LIBS`.
- **Evidence:** `&` expands to the match (`/tmp/r&lib` → `/tmp/r@ZUCRYPT_LIB@lib/...`); a
  `|` ends the expression; an apostrophe (`/tmp/O'Connor/...`) breaks the shell quoting
  in the generated Makevars.
- **Fix:** treat the three layers separately: escape `\`, `&` and the delimiter for
  `sed`; escape `'` for the shell quoting (or reject it with a clear message); and keep
  the make-level quoting. Mirror the fix in `configure.win`, the vignette and zuxlsx.
- **Test:** extend `tools/check-linking.sh`, which already uses a library path with a
  space, to paths containing `&` and `'`.

### A1 — NA logical silently picks the "false" branch

- **Severity:** robustness. Only internal `.Call` misuse reaches it, because the exported
  wrappers pass literals.
- **Location on `main`:** `src/zucrypt_crypt.c` l.357 (CBC `encrypt`), l.524 (GCM
  `encrypt`), l.632 (`private_key`), l.710 (`public_only`). All use
  `Rf_asLogical(x) == TRUE`.
- **Evidence (vibe, live):**
  ```r
  z <- zucrypt:::zucrypt_aes_cbc
  identical(.Call(z, as.raw(1:16), as.raw(1:16), raw(16), NA),
            .Call(z, as.raw(1:16), as.raw(1:16), raw(16), FALSE))   # TRUE
  ```
  GCM decryption then fails safely on the tag; the two key-I/O flags pick the
  public/full branch without saying so.
- **Fix:** one helper, `static int as_flag(SEXP x, const char *what)`, that raises an
  error on `NA_LOGICAL`, used at every site.
- **Test:** each `.Call` with `NA` must raise an error.

### A2 — Backend-teardown harness is registered in release builds

- **Severity:** latent. It is harmless today and becomes real once a table consumer holds
  handles across calls.
- **Location:** `src/zucrypt_test.c` `zucrypt_test_not_ready()` (l.484, registered at
  l.1115). It runs `zuc_shutdown()` → `mbedtls_psa_crypto_free()` → `zuc_init()`, which
  destroys every key in the process-wide store. A consumer's stale key IDs could then
  resolve to recycled slots.
- **Fix:** register the entry only when an environment variable is set at
  `R_init_zucrypt`, or have it refuse unless `zuc_int_live` is zero. The second fits the
  live counter that already exists and enforces the current comment ("safe only when no
  other context is live").
- **Test:** with one live `zuc_hmac`, the harness call must refuse.

### B5 — `libzucrypt.a` does not isolate the upstream symbols

- **Severity:** integration limitation.
- **Location:** `src/Makevars` (~l.32). `$(C_VISIBILITY)` isolates copies across *shared
  objects*, but the archive still defines `psa_crypto_init`, `mbedtls_*` and the rest.
- **Evidence (codex):** a consumer that supplies its own `psa_crypto_init` in the same
  shared object fails to link with a duplicate symbol. `check-linking.sh` covers separate
  shared objects only.
- **Fix:** decide on a policy. Either document "do not link another PSA/Mbed TLS into
  the same shared object as `libzucrypt.a`" in `?zucrypt_c_api` and the C-API article,
  or prefix the vendored symbols at build time (a `#define` map header, or
  `objcopy --prefix-symbols`, which is not portable). Documenting is the proportionate
  choice for ABI 1.
- **Test:** if documented, add a negative fixture asserting the documented failure mode.

### B6 — The registered-table header puns function pointers through a union

- **Severity:** portability. It is fine in C, where union type punning is defined
  (C99 TC3 / C11 6.5.2.3), and undefined in ISO C++, though GCC and Clang accept it as an
  extension.
- **Location:** `inst/include/zucrypt-r.h` ~l.199–205. The union is there to avoid
  `-Wcast-function-type-mismatch` under `-Werror`.
- **Fix:** under `#ifdef __cplusplus`, use `reinterpret_cast` (with the warning
  suppressed narrowly if needed). Keep the union for C.
- **Test:** add a C++ consumer that includes `zucrypt-r.h` and *calls* the table, not
  just `zucrypt.h`. `tools/zucrypttest` could grow one `.cpp` file.

### B7 — The ABI size test cannot see an overwrite

- **Severity:** test gap. The implementation looks correct today.
- **Location:** `src/zucrypt_test.c` `zucrypt_test_info_size()` (l.444). It allocates a
  full current `zuc_info`, lowers `struct_size`, and checks only the status. Writes to
  fields past the advertised prefix still land inside the object and are never
  detected.
- **Fix:** fill the struct (and guard bytes on both sides) with a pattern, set
  `struct_size`, snapshot it, call `zuc_get_info()`, then check that every byte past
  `struct_size` is unchanged and every field inside it is populated. Cover these sizes:
  below `ZUC_INFO_REQUIRED_SIZE` (expect `ZUC_ERR_ABI` with no writes); exactly the
  required size; one byte short of an optional field's end; exactly that end; and
  `sizeof(zuc_info)`.
- **Acceptance:** temporarily delete one size guard in `zuc_get_info()` in a scratch
  checkout; the test must fail. Later, add a fixture compiled against a frozen copy of
  the ABI-1.0 header.

### B8 — Allocation-failure workload accepts any plausible output

- **Severity:** test gap. No leak was shown.
- **Location:** `tools/alloc-exercise.R` (~l.54 at review time; `main` added 71 lines,
  so re-check). Digests are accepted if non-empty, HMAC by length only, and AES by round
  trip, which would miss a fault shared by encryption and decryption. Each injected
  failure also ends its process, so cleanup after partial construction and reuse
  afterwards are never observed.
- **Fix:** compare with fixed expected bytes. Add in-process targeted failure points
  (see B9) that catch the error, `gc()`, check the live count, and then run one
  known-answer operation.

### B9 — Lifetime tests may not reach the failure point they name

- **Severity:** test gap.
- **Locations and gaps:**
  - `tests/testthat/test-lifetime.R` (~l.41): the "native failure leaves no live
    context" test uses a bad AES key length, which fails *before* allocation, so cleanup
    after partial construction is never exercised.
  - The `setTimeLimit()` interrupt tests show that the limit fired and the count came
    back; on a slow or instrumented build they don't show that it fired while a context
    was live.
  - `tools/check-linking.sh` (~l.139) says both libraries hold live key state at once,
    but its wrappers create and free contexts one after the other.
  - The live counter increments only after successful construction, so it cannot see a
    leak during partial construction.
- **Fix:** add deterministic failure points as test-only harness hooks, outside the ABI
  and with no vendor edits. Cover: the adapter allocation; the backend setup after the
  allocation; HMAC setup after key import; an R error after the extptr owns the
  context; and a failure after the first chunk. Each case must show the expected error,
  the count back at baseline after `gc()`, and a correct next operation. For
  coexistence, hold contexts from both providers at once and interleave their updates.

### B10 — Vendor CI checks consistency, not reproduction

- **Severity:** CI gap. Codex reproduced the current tree from upstream exactly (113
  files).
- **Location:** `.github/workflows/vendor.yaml`. It checks the tree against the manifest
  and checksums, and that a vendor change touches the manifest. A hand edit recorded
  with `tools/vendor/record` but never made into a patch still passes.
- **Fix:** add a job (weekly or on vendor paths) that runs `tools/vendor/fetch` into an
  empty directory (pinned archive plus `tools/patches/`) and diffs the result against
  `src/vendor/`.

### B11 — `Rprofmem()` cannot see backend allocations

- **Severity:** test scope.
- **Location:** `tests/testthat/test-size.R` (~l.59). `Rprofmem` records R heap
  allocations only. PSA copies each update's input through
  `psa_crypto_local_input_alloc()` (`psa_crypto.c` ~l.9731), which the test cannot see.
- **Fix:** relabel the test as checking R allocation behaviour. If native allocation rate
  matters, measure it with an allocator shim. Do not disable the copying: it guards
  against shared-buffer attacks.

### A3 — `getrandom()` EINTR treated as entropy failure (fixed)

- At `fa0679a`, `src/zuc_random.c` returned `PSA_ERROR_INSUFFICIENT_ENTROPY` on any
  `n < 0`. On `main`, Stage 13a's rewrite includes `<errno.h>` and retries on `EINTR`
  (l.106–108). **Remaining:** codex's suggestion of an injectable syscall wrapper to test
  short reads, EINTR and permanent errors still applies.

### Policy note — software AES timing

The table-based fallback leaks key material through cache timing, as upstream's
`SECURITY.md` warns. It is documented and reported through `crypt_info()`. A deployment
may want a "refuse without hardware AES" option. That is an acceptance decision, not a
defect.

## Verified clean (from vibe, at `fa0679a`)

Kept as evidence. Read A4 and A6 together with B1, because both rest on lengths that R
reports.

- **A4, SEXP contract:** arities match their registrations. Algorithm names are exact,
  scalar and non-NA, with no partial matching. Key and data lengths are re-checked in
  the adapter. Unclassed type confusion is caught by the checked accessors. *Not covered:
  classed raw vectors (B1).*
- **A5, PROTECT discipline:** PROTECT and UNPROTECT balance on every path. `result()` is
  always called while `out` is protected. The extptr and finalizer exist before the
  context. `release_ptr()` clears the pointer before freeing it.
- **A6, NA/NaN/Inf:** there is no double input. The only NA leaks are A1 and the
  intentional `Rf_asInteger` tolerance in the harness.
- **A7, long vectors:** sizes are `size_t`, and the 1 MiB chunk is a multiple of 16.
  `raw(2^31 + 32)` hashes and round-trips byte-identically to `openssl`, and a 3 MiB+16
  CBC input matches `openssl enc -nopad`.
- **A8, allocation and lifetime:** `calloc` results are checked, `*out = NULL` is set
  first, and partial contexts are destroyed. Interrupting a hash, AES or a connection
  loop leaves the count at 1 until `gc()` and 0 after it.
- **A9, no input mutation:** outputs are always fresh; `zuc_int_overlaps` is correct.
- **A10, vendored patches:** 0001 (`MBEDTLS_PK_MAX_PUBKEY_RAW_LEN` 0→1) and 0002 (pragma
  removal) are balanced and benign; PSA usage follows the contract. *`main` has since
  added a `psa_aead_finish` patch, which this review did not cover.*
- **A11, build and registration:** registration is complete, `useDynamicSymbols(FALSE)`
  and `forceSymbols(TRUE)` are set, `Makevars` is portable, and every return in
  `install.libs.R` is checked. *See B3 for the missing dependencies.*
- **A12, R validation and connections:** exact matching; connections are refused when in
  text mode, not readable, or non-blocking and incomplete (`isIncomplete`); `gzfile`
  works; condition calls are redacted.

Codex independently confirmed: 1,076 expectations pass, both consumer fixtures pass, the
vendor and layering checks pass, and the 113 vendored files reproduce from upstream.
